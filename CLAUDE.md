# Regras PrismView & Economia
- Respostas ultra-curtas. Sem saudações, introduções ou resumos longos.
- Nunca leia `node_modules/`, `target/`, `.git/`, `dist/`, `.glb`, `.gltf`, `.png`, `.jpg`, `package-lock.json`.
- Leia apenas os arquivos estritamente necessários para a tarefa atual e aplique patches pontuais.
- Regras técnicas: nunca alocar objetos/vetores dentro de loops de render 60–144 FPS; sempre chamar `dispose()` em geometrias, materiais e texturas 3D descartadas (exceto texturas compartilhadas em cache).

# Projeto
- PrismView Studio: wallpapers/widgets animados, só Windows. Tauri 2 + React 18 + Three 0.187 + Tailwind 3 + Vite 6 + framer-motion + lucide-react.
- Raiz app: `apps/prismview-studio/`. Scripts: `npm run dev` (porta 1420 strict), `npm run build` (tsc + vite), `npm run tauri`, `npm test` (node --test, só FX). Sem lint.
- Duas entradas Vite (`vite.config.ts`): `index.html`→`src/App.tsx` (Hub + Studio, janela `main`) e `desktop.html`→`src/desktop.tsx` (leve: sem Hub/Studio/framer-motion). Chunks: `three-core`; `three-editor` (gizmos Sala 3D, só Studio).
- `desktop.tsx`: só `?mode=widget&id=<id>` (widget transparente standalone, drag/lock/unpin). Wallpaper WebView removido (Lote 6B): quem desenha é o `prismview-engine --native`.
- Dados em `%APPDATA%\PrismView\` (`projects/<id>.json`, `packages`, `imports`, `fonts`, `assets`, `session.json`). Pacote `.prism` = zip.
- Tauri: CSP restrita (+`devCsp`), asset protocol scope `$DATA/PrismView/**` (= `%APPDATA%\PrismView`); arquivos escolhidos fora disso entram em runtime via `ASSET_SCOPE.allow_file` (`pick_local_file`, `load_project_from_disk`, `list_projects` → `allow_project_media`). `bundle.active=false`.

# `crates/prismview-engine` (motor nativo, Fase 0 em andamento)
- Meta (PLANO_NATIVO.md, fora do repo, em `Downloads`): wallpaper 100% nativo Rust + wgpu (DX12) + Win32, sem WebView; Studio Tauri só edita. - Regras do plano: zero `unwrap/expect` no loop de render (SurfaceError::Lost/Outdated → recriar swapchain); zero alocação por frame (buffers pré-alocados + `.clear()`); render targets só recriados em resize/troca de asset; vídeo sem cópia/conversão BGRA→RGBA na CPU; `core/` (futuro: gpu, glass, scene3d, text, signals, governor) nunca importa código de SO — só fala via traits de `platform/mod.rs`.
- `main.rs`: só `mod`s + `native::run()` (host legado, ab_glyph e decoder de vídeo CPU `video.rs` removidos). `ipc_server.rs`: named pipe (`IpcEnvelope`). Binário sempre em modo nativo (flag `--native` aceita e ignorada).
- `platform/mod.rs`: traits neutras `DesktopHost`, `HardwareVideoDecoder`, `SystemSensors` + tipos (`MonitorInfo`, `DesktopEvent`, `DesktopVisibility`, `NativeWindowId`, `PlatformError`); `UnsupportedPlatform` para não-Windows.
- `platform/windows/` (só `DesktopHost` implementado; vídeo/sensores TODO):

# Armadilhas
- Widget é outro WebView e o wallpaper é o motor nativo: `blob:` URL não atravessa; salvar caminho real/asset (`PickedFileDto` via `pick_local_file`).
- Backdrop 3D do vidro é canvas `live`: re-upload por frame.
- Textura dinâmica (capa de música) vem de `dynamicTexCache`: compartilhada, não dar `dispose()` ao descartar modelo; devolver `baseMap` antes.
- Perda de contexto WebGL: refazer PMREM/ambiente no restore.
- Hub: miniaturas usam `HubThumbnail` (memo, telemetria fixa, `paused`); cada uma pode custar um WebGL.
- `AUDITORIA.md`: bugs/vazamentos priorizados (Etapa 1 primeiro). Consultar antes de mexer em 3D/vidro.
- Lixo/backup, ignorar: `_backup_antes_sala3d/`, arquivo `e.restoreContext()`. `.claudeignore` espelha a lista de não-leitura.
